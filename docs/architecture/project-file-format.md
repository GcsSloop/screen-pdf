# 项目文件规范：可移动的 v2 格式

2026-10-17 更新。此规范适用于桌面程序写出的项目文件，人工点位结构仍保持 `dataStructureVersion=2`；文件存储格式以 `version=2` 区分。

## 唯一存储位置

一个项目目录只写一个 `<项目根目录>/screen-pdf-project.json`。保存按钮直接保存到这里，取消任意路径“另存为”。导出前也在根目录保存当前状态，不往导出目录写项目副本。临时写入使用同目录临时文件，再原子替换正式文件。

不会扫描、批量删除原有项目目录中的历史文件。读取旧导出子目录中的项目副本时，若祖先已有根项目文件，则使用根文件；无根文件但旧导出副本可定位父目录原图时，保存会迁回原图根目录。

## 路径契约

保存到磁盘的 JSON：

- `sourceDir` 固定为 `"."`。
- `projectPath` 固定为 `"screen-pdf-project.json"`。
- `pages[].path` 从根目录出发，使用 `/` 分隔的相对路径，如 `"IMG_1502.jpeg"` 或 `"photos/IMG_1502.jpeg"`。
- 禁止绝对路径及越出项目目录的 `..`。需要保存的原图必须位于项目目录内；不把外部图片引用悄悄复制或写成不便携的路径。
- `thumbPath`、`previewPath` 是可再生缓存，写入 `null`，不保存临时目录或本机缓存路径。

运行时内存中的路径会由当前 JSON 所在位置恢复为可访问的绝对路径，供图片显示、推理和导出使用。磁盘格式与内存格式不能混用。

旧绝对路径优先按原 `sourceDir` 的相对子路径映射到当前位置，再尝试同名图片，最后才保留旧外部路径用于兼容读取；复制项目后即使旧目录仍在，也优先读新目录。保存外部引用时会提示将原图放进项目。旧 Windows 路径也能在其他系统下重定位。人工四角点、候选原始点、页面状态、顺序和标签保持原值。

## 名称与导出

项目名唯一来源为当前根目录的目录名，磁盘文件不再保存 `name`。读取旧文件时忽略过时的 `name`，从新位置恢复。

默认 PDF：`<项目根目录>/<当前目录名>.pdf`。可另选导出目录，但文件名仍为 `<当前目录名>.pdf`，派生资料目录为 `<当前目录名>_export/`。保留中文、空格和 `2.0` 等名称中的点号。

例如目录从“旧名称”改成“元宇宙 2.0 新名称”，重新打开项目后导出为“元宇宙 2.0 新名称.pdf”，派生目录为“元宇宙 2.0 新名称_export”。外部移动/改名后需要从新位置重新打开项目；当前没有对操作系统目录改名做实时监听。

## 示例（省略其余页面元数据）

```json
{
  "version": 2,
  "dataStructureVersion": 2,
  "sourceDir": ".",
  "projectPath": "screen-pdf-project.json",
  "selectedPageId": "IMG_1502",
  "pages": [{
    "id": "IMG_1502",
    "name": "IMG_1502.jpeg",
    "path": "photos/IMG_1502.jpeg",
    "thumbPath": null,
    "previewPath": null,
    "candidates": [],
    "activeQuad": []
  }]
}
```

机器可读约束见 `docs/schemas/screen-pdf-project-v2.schema.json`。规范描述存储层；实际页面还包含创建时间、状态、置信度与人工候选等业务字段。

## 训练与评估兼容

Python 的 `project_file.py` 统一根目录路径解析；训练/评估导入时生成自己的绝对路径快照，不能直接把项目 JSON 的相对路径当作进程工作目录路径。发现项目时不重复读取已识别项目根目录之下的旧导出副本。

已有训练快照、标注和实验权重不批量迁移或覆盖。已有项目在下次显式保存或导出时升级存储格式，无需重做人工角点。

打开旧格式仅兼容读取，不自动覆盖原文件；用户保存或导出时统一写入上述 v2 新格式。重新打开保存后的文件，人工角点、候选点位、页面状态、顺序与标签继续保留。
