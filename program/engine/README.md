# Engine

`engine` 当前采用“兼容根层 + 分组子层”的过渡结构。

## 为什么这样做

- 根层保留原有模块文件，避免历史脚本、测试和打包资源一次性全部失效。
- `runtime / training / eval / tests` 提供按职责划分的浏览入口，方便后续继续收口。

## 子层

- `runtime`
  - 运行时检测、候选融合、三阶段推理主链路。
- `training`
  - 训练脚本、训练数据组织、调参与实验注册。
- `eval`
  - 评估、benchmark、回归对比与分析脚本。
- `tests`
  - 测试入口分组视图。

## 当前约定

- 新增脚本优先放进对应子层。
- 根层暂时保留为兼容层。
- 等桌面程序、训练脚本和测试入口都切换完成后，再决定是否移除根层兼容文件。
